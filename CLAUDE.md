# Prism Web — notes for Claude

The Prism suite website: one home page + one guide page per app, where visitors learn each app on its **real screens**
(point at any part → glowing frame + explain box; "what do you want to do?" demos with a ghost cursor; Ctrl+K search
across every app). Static site (HTML/CSS/plain scripts, no build step — **must work by double-click / file://**, so no ES modules or fetch) → GitHub Pages. TH/EN, light/dark, Prism glass theme.
Built 2026-11-21 at the user's request ("อลังการ เรียบหรู ดูง่าย แปลกใหม่ — เน้นระบบสอน").

Read first: `../CLAUDE.md` (suite rules) and `../docs/LESSONS.md`. More: `docs/features.md`, `docs/pitfalls.md`, `docs/changelog.md`, `docs/ideas.md`.

## Layout
- `index.html` + `js/home.js` — hero, 2D orbit of app logos (own ring each, Player⇄Studio pair), app cards (live GitHub version), mini live guide (Prism Cam), install steps.
- `<app>.html` — generated by `node tools/pages.js` (never edit by hand); all load `js/app-page.js` (`data-app` on body).
- Scripts share `window.Prism` (functions), `window.PrismData` (apps), `window.PrismGuides`, `window.PrismShots`; load order
  is in `tools/pages.js` (copy it into `index.html` if it changes).
- `js/core.js` — language (`prism.lang`), theme (`prism.theme`) — same keys as the apps — top bar, Ctrl+K palette
  (index built from every `data/guide/*.js`, Thai fallback = 2-letter piece coverage), reveal, GitHub releases (cached per visit).
- `js/guide.js` — the guide engine (spots, explain box placement, side list, tour, demos/ghost cursor, phone zoom, deep links
  `#spot=<screen>.<spot>` / `#demo=<id>`).
- `js/bg.js` — Prism WebGL background (still gradient on phones / reduced motion).
- `data/apps.js` — catalog (name, logos, repo, colours, tagline, stack). `repo` set = download button asks GitHub.
- `data/guide/<app>.js` — all guide text, `[Thai, English]`: `screens[{id, title, hot{id:{t,d,tip,keys,r?}}}]`, `demos`, `feats`, `keys`, `faq`.
- `data/shots/<app>.js` — spot boxes per screen per `theme.lang` (written by the capture tool). `shots/<app>/<screen>.<theme>.<lang>.webp`.

## Screenshots + spot boxes (`tools/capture/`)
- `main.js` (run with Prism Size's Electron): loads an app's real renderer page off-screen, drives it, saves WebP + the
  exact boxes of CSS selectors. `env -u ELECTRON_RUN_AS_NODE ../prism-size/node_modules/electron/dist/electron.exe tools/capture/main.js tools/capture/jobs/<app>.js [shot,…]`
- Jobs: `cam` `code` `size` `rec` `voiceopen` (+ `recbar`, `voglow` = re-drawn overlays from `mock/index.html`).
  Bridges (`bridges/*.js`) fake `window.prism` / `window.__TAURI__` with **made-up demo data** (demo drive D:\, demo
  recordings, demo voice commands). `jobs/probe.js` (PROBE_APP / PROBE_SHOT / PROBE_JS) prints DOM structure, writes nothing.
- Player / Studio are native: `media-shots.ps1` opens them on `C:\Users\Public\Videos\Prism demo.mp4`, topmost, copies
  only the window rect; spots are hand-placed (`r:` in `data/guide/media.js`). Look at every image before publishing.
- After changing an app's UI: re-run its job, then check `data/guide/<app>.js` spots still exist (missing selectors are logged).

## Rules specific to this site
- **Privacy**: screenshots are public. Never capture real user data, file paths with the user name, the desktop, or the
  Rec bar / VoiceOpen glow for real (they refract the user's screen) — those two are re-drawn in `mock/`.
- **Credit Claude AI.** The user made these apps with Claude AI — never write "designed/built by me" alone; say
  "สร้างด้วย Claude AI" / "made with Claude AI" (also in My-Web).
- Every visible string is `[th, en]` (or `data-t="ไทย|English"` in HTML).
- New app → entry in `data/apps.js`, `tools/pages.js`, a guide file, a capture job, logo in `img/logos/`.
- Publishing (new repo / push) is the user's call — ask first.
